`draft: true` combined with the `import.meta.env.DEV` filter in
`getPublishedPosts()`. Open it under `astro dev` to eyeball the layout
whenever the blog templates change.

## Fenced code

```ts
import { getCollection } from 'astro:content'
import readingTimeFn from 'reading-time'

export async function getPublishedPosts() {
  const includeDrafts = import.meta.env.DEV
  return (await getCollection('blog'))
    .filter((p) => includeDrafts || !p.data.draft)
    .sort((a, b) => b.data.date.getTime() - a.data.date.getTime())
}
```

And a shorter one to check tight spacing:

```bash
npm i @astrojs/rss reading-time
```

  Tips highlight a recommended path. Slightly accented so they pop

A warning callout for caveats:

  Warnings call out footguns and deprecations. Use sparingly so the

The `<TechHeavy>` wrapper is a `<Callout type="warning">` with a
default title — for sections that get into the weeds:

<TechHeavy>
  Below this banner, expect implementation details that won't matter
  for casual readers but will matter for the next person debugging it.
</TechHeavy>

The `<ComingSoon>` wrapper is a `<Callout type="tip">` with a default
title — for things shipped behind a flag or pending an upstream
release:

  Once the upstream package lands, this section will replace the
  manual workaround above.
</ComingSoon>

A screenshot using an existing app asset — drives the `<figure>`
spacing, rounded border, and optional caption:

  caption="A real screenshot reused from the home page — fixture only."
